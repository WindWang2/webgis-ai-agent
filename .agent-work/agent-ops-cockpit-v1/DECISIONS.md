## D2 — Tenant/auth discipline identical to mission_runtime.py

`org` via `tenancy.effective_org_in_thread(user)` (`app/core/tenancy.py:206`), `user_id` via `get_current_user` (`app/core/auth.py:304`). Every durable read is org-scoped exactly like `get_mission(mission_id, org_id=...)`. Session-scoped process-local reads (skill/evidence/trace) resolve the session through the mission's `refs.active_session_ids` when a mission is supplied, and additionally constrain to the caller's org when a mission binding is derivable; otherwise they serve only the explicitly requested `session_id` — process-local in-memory data that never crosses process boundaries. No new auth surface; no `ownerToken` support on cockpit routes (they are JWT surfaces, unlike `/chat/sessions/*`).

## D3 — Bounded payloads everywhere (Zero Big Data)

Reuse the contracts' own bounds: checkpoints ≤32/list (`store.py:547` caps at 32), trace ≤64 records/session (`trace_store.py:41` `MAX_RECORDS_PER_SESSION`), frontier ≤64/bucket (`MAX_FRONTIER`), refs ≤64/bucket (`MAX_REFS`), swarm tasks ≤48/run (`MAX_SWARM_TASKS`), summaries ≤400 chars (`MAX_SUMMARY_CHARS`). Cockpit list endpoints take `limit` (default 50, max 200, mirroring geocompute events) and return `poll_after_ms` + `has_active` following the `JobListResponse` protocol precedent (`frontend/lib/api/jobs.ts:53-58`) so the frontend never invents polling cadence.

## D4 — Frontend transport: revision-guarded polling store, not a second SSE stack

`use-sse-stream.ts` is a 1300+-line chat-coupled hook (INV-2 session guards at lines 543-553, MapSpec CAS, token batching); coupling the cockpit to it would entangle two views. **Decision:** cockpit store ingests transport-agnostic snapshots via a single `applySnapshot(kind, payload, meta)` with:
- `revision` monotonic guard (drop snapshots with revision < current; equal revision = idempotent no-op) — mission `revision`/`goal_revision` and swarm-run `revision` are already monotonic server-side (lease-epoch CAS),
- epoch/session tag on every in-flight request; responses from a superseded session are dropped (session-switch isolation — same discipline as INV-2 and `use-session-plan.ts`'s clear-before-fetch),
- abort controllers aborted on session switch/unmount,
- poll loop driven by server `poll_after_ms` (bounded 1s–30s), paused when `document.hidden` — implement on top of the existing bounded-poll kernel `useBoundedPoll` (`frontend/lib/hooks/use-cluster-poll.ts`: min interval 3s, stop after 3 consecutive errors, generation guard, visibility pause) and the cursor channel pattern `use-cluster-run-events.ts` (`after_id`/`after_seq` accumulation, 500-event ring, terminal stop, 404 → honest `'notfound'`).

**Rationale (SSE vs polling):** the only SSE stream (`POST /api/v1/chat/stream`, `chat.py:1020`) is turn/session-scoped with a transient 256-event process-local resume buffer (`event_resume.py`; cross-restart explicitly out of scope); WS (`ws.py:30`) is session-scoped JWT. No mission-scoped push exists; building one requires cross-pod fan-out (ADR-0197 D3 leases) for low-frequency state changes. Bounded cursor polling reuses tested primitives and survives restarts. The snapshot applier is transport-agnostic, so an additive cockpit SSE stream can be attached later without UI changes (documented extension seam, not built in v1).

## D8 — Honesty rules

- Process-local claim/skill/trace data is labeled "current process only" (server restart clears it; `HotpathTurnContext` evicts at 256 sessions; trace window is 64 records) — no fake persistence claims.
- No frontend re-derivation of mission state: UI renders server `state`/`frontier` verbatim; derived bits (e.g. "is action enabled") come from a whitelist per server state mirroring `TRANSITIONS` (`contracts.py:56-90`), and the server remains the enforcement point (409 surfaces).
- Operator actions: constant `worker_id="ops-console"`; confirm dialog names the action, current state, and revision; 409 renders "lease held by {lease_owner} (epoch {lease_epoch})" with re-GET+retry; 503 renders "mission runtime disabled"; terminal states (`complete|failed|cancelled`) disable all actions. Transport never auto-retries POSTs (`transport.ts` IDEMPOTENT_METHODS guard) — keep it that way.
- Secrets/CoT: trace/evidence projections expose only structured decision evidence already designed for disclosure (bounded `to_bounded_dict` outputs; pi_card banned-key strip as the server-side precedent); anything failing the hygiene check is omitted server-side, not masked client-side. `step_result.arguments` and `is_reasoning` token content never enter cockpit payloads.
