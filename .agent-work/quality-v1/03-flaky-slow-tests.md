# Flaky & Slow Test Audit — static analysis (quality-v1, report 03)

Scope: `tests/` (793 test files, pytest, asyncio_mode=auto, timeout=60/thread) + `frontend` vitest (254 test files). Read-only analysis; no suite runs. All paths relative to repo root.

---

## 1. Executive summary

- **Overall posture is unusually good for a suite this size.** The team has already fought and documented its flakiness wars: `pytest.ini:24,26` and `tests/conftest.py:128-154` isolate perf baselines (`-m perf` only, #664), `tests/conftest.py:18-104` pins a full env baseline (#663-B), `tests/conftest.py:157-194` fails fast on HuggingFace model downloads (#660), real services are opt-in via `REAL_SERVICES=1` (#661), and `tests/test_ci_perf_coverage_contract.py:31-42` contract-locks wall-clock perf files to the nightly lane. No test opens sockets or hardcoded ports; Celery runs eager on `memory://`; Redis is faked.
- **The residual risk is concentrated in three systems:**
  1. **Concurrency/heartbeat tests built on real sleeps** (Pi bridge, SSE keepalive, event-loop offload, tool-metrics file writer). ~66 `time.sleep`/`asyncio.sleep` calls with non-zero durations across 30 files; several pair a *stimulus* sleep (0.02–0.15 s) against an *assertion* deadline, which is a race under CI load.
  2. **13 benchmark files inside `tests/benchmarks/` + `tests/perf/` that carry no `perf` marker** and therefore run in the main CI lane (under `--cov`), several with median wall-clock assertions the repo itself calls "flaky under PR load" elsewhere.
  3. **Unseeded global randomness in ~60 of 83 spatial/GIS test files** (only 22 files set any seed). Most are statistically tolerant today, but any future exact-value assertion inherits a nondeterministic data generator.
- **Slowest known items:** `tests/test_jenks_441.py:137,148` (`@pytest.mark.timeout(240)`, reference DP takes tens of seconds per classify), `tests/test_event_loop_offload_565.py:157-211` (fake DB rows sleep 2.0 s each), 100k-feature fixtures in `tests/unit/test_performance_100k.py` and `tests/fixtures/mapspec_cow_fixtures.py`.
- **Frontend** is largely clean (`vi.useFakeTimers` in 12 files, `maplibre-mock-surface` instead of real WebGL); the main offender is `map-panel.cartography-race.test.tsx`, which waits out real 900 ms reset windows with raw `setTimeout`.

## 2. Systemic causes (ranked)

1. **Sleep-synchronized concurrency tests (highest flake risk).** Tests for the Pi turn lock, SSE keepalives, offload, and cancellation can't use fake clocks because they assert *real* event-loop liveness. They instead use `asyncio.sleep(x)` as a progress oracle: e.g. `tests/test_sse_planner_keepalive_435.py:71-72` (heartbeat pinned to 0.02 s, planner sleeps 0.10 s, comment literally says ">> heartbeat interval, << test budget") and `tests/test_pi_bridge_lock.py:126` (`await asyncio.sleep(0.15)  # a few heartbeat intervals elapse`). A GC pause or loaded runner compresses the ratio and the assertion flips. Note the repo already knows this pattern is fragile: `tests/test_ci_perf_coverage_contract.py:36` calls an event-loop-lag wall-clock assertion "flaky under PR load / --cov".
2. **Marker-coverage gap in the perf directories.** The #664 conftest skip (`tests/conftest.py:128-154`) only protects items carrying `pytest.mark.perf`. 13 files in `tests/benchmarks/` and `tests/perf/` have no marker (see §4 list), so millisecond-median assertions (`tests/benchmarks/test_gis_registry_perf.py:16-21` `_median_ms(fn, n=50)`, `tests/benchmarks/test_planner_runtime_perf.py`) execute in the main `--cov` lane where the repo's own contract says wall-clock medians flake.
3. **Unseeded global RNG.** 83 test files use `random`/`np.random`; only 22 seed anything. Global `np.random.normal(...)` fixtures (e.g. `tests/test_spatial_stats.py:87,202,219`) make every assertion downstream depend on suite execution order for its random stream. Today most assertions are tolerance-based, so this is latent — but it also *hides* order dependence and blocks a future repetition runner from reproducing failures.
4. **Polling against background writers with wall-clock budgets.** The tool-metrics async writer is polled by several suites with `time.monotonic() + 5.0` deadlines (`tests/test_registry_timing.py:28-47`, `tests/test_tool_metrics.py:28-46,232-240`, `tests/test_kde_contours_caching.py:66-75`, `tests/test_h3_binning_caching.py:69`) and the job watchdog with a 10 s loop (`tests/jobs/test_job_worker.py:173-177`). These degrade to 5–10 s stalls under load instead of failing fast, and a torn final line is handled by retry, not by a deterministic flush hook.
5. **Long real sleeps used as "slow work" stand-ins.** `tests/test_event_loop_offload_386.py` (7× `time.sleep(0.8)`), `tests/test_event_loop_offload_565.py` (5× `time.sleep(2.0)` fake DB rows), `tests/test_sse_planner_keepalive_435.py:155` (`sleep(2.0)`), `tests/test_token_refresh.py:265` (`time.sleep(1.1)` to outlive JWT clock granularity). These are deterministic but add tens of seconds of pure waiting to every run; the token-refresh one is also a disguised clock-granularity hack.
6. **Module-attribute and singleton mutation without restore.** A handful of tests patch module globals or settings directly (`ws_module.get_rate_limiter = _stub` in `tests/test_ws_auth.py:33-37`, `settings.RASTER_PROCESSING_MEMORY_MB = 1` in `tests/unit/test_raster_runtime_v3.py:324`, import-time `os.environ` writes in `tests/benchmarks/_master_context_baseline.py:30`). Most of the suite correctly uses `monkeypatch`, so these outliers are the only cross-test contamination vector left.
7. **Missing infrastructure for detection, not prevention.** No `pytest-xdist`, no `pytest-randomly`, no `freezegun` in `requirements-dev.txt:10-15`. Consequences: order-dependent bugs are invisible (single, fixed order), repro-of flakes is manual, and wall-clock tests can't be converted to frozen time without adding a dependency.

## 7. Recommendations — flaky-test eradication program

1. **Marker hygiene sweep (cheap, immediate).** Add `pytestmark = pytest.mark.perf` (or rewrite as counter contracts) to the 13 unmarked files in §4; extend `test_ci_perf_coverage_contract.py` to assert *every* file under `tests/benchmarks/` and `tests/perf/` is either perf-marked or declares a documented deterministic header — the directory-vs-marker ambiguity is exactly the bug class #664 fixed for marked items.
2. **Repetition runner.** Add `pytest-flaky`-style or custom `--count=N` rerun (pytest-repeat) plus `pytest-randomly` (seeded, logged in CI). The suite currently has zero order-shuffling, so the order-dependence findings (#20, #22, #23, #24) are invisible. Run `-p no:randomly` locally when bisecting; nightly run with `--count=5 -x` over the §3 timing-flagged files first.
3. **Seed policy.** Ban bare `random.`/`np.random.` in `tests/` (import-linter or a simple `grep` CI check, mirroring `test_ci_perf_coverage_contract.py` style): require `random.Random(seed)` / `np.random.default_rng(seed)` instances with per-file constant seeds. Migration is mechanical for the ~60 unseeded files.
4. **Fixture policy.** (a) `tmp_path`/`monkeypatch` only — no bare `tempfile.mkdtemp`, no direct `settings.X =` or `module.attr =` mutation (findings #20-#24); enforce via code review checklist and a ruff flake8-bandit-like custom rule. (b) Shared "drain background writer" fixture replacing the four copy-pasted 5 s poll loops (#7-#9). (c) Session-scoped caching for >10k-feature synthetic payloads, extending `tests/fixtures/mapspec_cow_fixtures.py:60-62`.
5. **Clock policy.** Add `freezegun` to `requirements-dev.txt`; require it for any test that constructs timestamps relative to `datetime.now()` for boundary assertions (#6, #28). For heartbeat/offload tests where a fake clock would defeat the purpose, mandate the event-based progress oracle (assert a *side effect happened*, never that *time elapsed without happening*).
6. **Slow-test budget.** The 60 s/thread per-test timeout hides cumulative slowness. Track per-test durations (pytest `--durations` artifact uploaded in CI); set a soft 5 s budget for unmarked, non-heavy tests and gate new offenders. Quick wins: #2 and #3 remove ~30 s of pure sleep; #1 removes 1-4 min.
7. **Keep the strengths.** Do not regress the existing contracts: env baseline (#663), perf isolation (#664), REAL_SERVICES arming (#661), embedding fail-fast (#660), and the nightly-only perf file list — each encodes a real incident and is itself tested (`tests/unit/test_env_hygiene.py`, `tests/unit/test_perf_isolation_wiring.py`, `tests/test_ci_perf_coverage_contract.py`).
