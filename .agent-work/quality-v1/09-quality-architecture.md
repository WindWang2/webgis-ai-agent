# 09 — Quality Architecture Synthesis (Quality Platform Foundation Map)

> Repo snapshot: `webgis-ai-agent-quality-v1` (read-only audit, 2026-09-08).
> Scope: existing quality infrastructure — gates, registries, generators, drift
> tests, CI lanes, certification precedents — as the substrate for a generative
> QualityManifest / contract-drift-gate / trace-validation / certification platform.
> All paths relative to repo root unless absolute. Line numbers from this snapshot.

---

## 1. Executive summary

The repo already runs a mature, *derivation-first* quality architecture with a
single, explicit rule: **registries are truth; everything else (docs, catalogs,
oracles, manifests) is a deterministic projection, and every projection is
paired with a drift test that fails on staleness.** Four projections exist today:

1. **Doc projections** — `docs/science/ALGORITHM_CATALOG.md` ← Capability +
   Algorithm + ParameterContract registries (`scripts/gen_science_catalog.py`),
   byte-diff drift test at `tests/unit/gis/test_foundation_v2_infra.py:172`;
   `docs/workflows/workflow-catalog.md` ← RecipeRegistry
   (`scripts/gen_workflow_catalog.py --check`), drift test
   `tests/unit/gis_harness/test_workflow_guards.py:357`; five
   `docs/cartography/*-catalog.md` files ← cartography model/component/theme
   registries (`python -m app.lib.cartography.catalog_docs --check`), drift test
   `tests/cartography/test_catalog_docs.py:20`.
2. **Data projections** — 12 frozen numerical-oracle JSON corpora (1,084 replay
   cases) generated by `scripts/gen_science_oracles.py`, replayed without
   recomputation by `tests/science_oracles/test_oracle_replay.py`.
3. **Runtime projection** — `compile_runtime_manifest()`
   (`app/lib/gis/runtime_manifest.py:201`) projects all three registries into a
   fingerprinted manifest with `fatal/warning/planned` severity classification;
   startup fail-fast under `GIS_MANIFEST_STRICT`.
4. **CI-contract projections** — `scripts/ci-local.sh` mirrors
   `.github/workflows/production.yml` lane-by-lane; the mirror itself is pinned
   by contract tests (`tests/test_ci_local_gate_contract.py`,
   `tests/test_ci_perf_coverage_contract.py`) so workflow drift turns red locally.

**Gaps a Quality Platform must fill** (not replace): (a) the descriptor
coverage gate is **currently broken in this snapshot** —
`tests/unit/test_descriptor_coverage_gate.py:9` imports
`scripts/check_tool_descriptor_coverage.py`, which does not exist here (only 6
files in `scripts/`); (b) there is no single machine-readable *quality* artifact
— quality facts are scattered across descriptor fields (`scientific_status`,
`uncertainty_outputs`, `conformance_tests`, `scale_class`, `latency_class`),
manifest issues, oracle corpora, and CI config; (c) trace validation exists
(`app/evaluation/replay.py` — three deterministic replay modes) but is not tied
to any gate artifact. The correct integration shape is **extend the existing
projection pattern**: a QualityManifest generated *from* the same registries +
descriptor introspection, committed as a doc/data artifact, pinned by a byte-diff
drift test, with thresholds stored once and consumed by both gate and manifest.

## 2. Gate inventory

compare to committed file; **contract test** = assert structural relationship
between two files/objects (workflow ↔ script, schema ↔ registry); **ratchet** =
numeric floor enforced in CI + mirrored in a contract test; **corpus replay** =
frozen expected values replayed without recomputation; **manifest gate** =
in-process registry validation with severity classes.

### 3.2 End-to-end generator pipeline (the canonical pattern)

```
SOURCE OF TRUTH (in-app registries, domain packs)
  app/lib/gis/capabilities/*.py, app/lib/gis/algorithms/*.py,
  app/lib/gis/parameter_contracts.py (aggregated from packs)
        │  import registries (scripts do sys.path.insert(ROOT) — gen_science_catalog.py:18-23)
        ▼
GENERATOR (deterministic pure function, sorted iteration)
  scripts/gen_science_catalog.py::generate() → str        (doc string)
  scripts/gen_workflow_catalog.py::render_catalog() → str (with --check mode, :155-172)
  app/lib/cartography/catalog_docs.py (module entry, --check mode)
        │  "same registry state ⇒ byte-identical output" (gen_science_catalog.py:11)
        ▼
COMMITTED ARTIFACT (projection, "请勿手工编辑" banner in header)
  docs/science/ALGORITHM_CATALOG.md (1,104 lines)
  docs/workflows/workflow-catalog.md (2,118 lines)
  docs/cartography/{map-model,component,composition-template,theme-palette}-catalog.md, renderer-parity-matrix.md
        │
        ▼
DRIFT TEST (re-runs generator in-process, compares to committed bytes)
  G1 / G2 / G3 — failure message always carries the regen command
```

Oracle variant (data instead of docs): generator computes expected values from
independent reference formulas once, on a dev box
(`gen_science_oracles.py:1-20`: "expectations from independent reference
formulas; implementation-regression anchors flagged `anchor: true`"), writes
deterministic byte-ordered JSON (`r9()` rounding at `:78-82` for stable round
trips); replay side (`test_oracle_replay.py`) is zero-recompute, offline.

Key invariants of the pattern (all four instances obey them):

- exactly one truth (registry); artifact header says so and names the regen command;
- generator output is deterministic (sorted ids, `(priority, id)` order matching
  `AlgorithmRegistry._by_capability`, bounded text, fixed precision);
- drift test re-derives rather than hashes, so failure message can instruct the fix;
- generators may offer `--check` (workflow, cartography) but the *gate* is the
  pytest wrapper, which is what puts it in a CI lane.

### 3.3 Where a generative QualityManifest fits (no second source of truth)

The pattern already contains the answer: **a QualityManifest is one more
projection over the same registries, generated by the same style of script,
pinned by the same style of byte-diff test.** Specifically:

- Inputs must be *existing* truth: `ToolRegistry.all_metadata()` / descriptors
  (quality fields incl. `side_effect`, `scale_class`, `security_tier`,
  `failure_modes`), `AlgorithmDescriptor` (`scientific_status`,
  `conformance_tests`, `uncertainty_outputs`, `random_seed_policy`,
  `backend_variants` scale windows), `CapabilityRegistry` (`deterministic`,
  `supports_large_data`), `compile_runtime_manifest()` issues/fingerprint, and
  *discovered* test outcomes (e.g., verify `conformance_tests` node ids resolve —
  the validator already does existence checks, `algorithm_registry.py:151-158`).
- A manifest compiled at startup already exists
  (`runtime_manifest.compile_runtime_manifest`, projects capability/algorithm/tool
  triples + fingerprint + issue severities). A QualityManifest should be defined
  as **the quality slice of that same compilation** — reuse `_project_tool` /
  `_project_algorithm` projection helpers (`runtime_manifest.py:151-199`) rather
  than re-introspecting registries with new code. That is the single strongest
  anti-second-source move available: same projection functions, different
  rendering target.
- Never hand-edit the manifest artifact; any manual quality prose belongs in
  ADRs/docs, not in the generated file (existing banners enforce this).

## 4. ADR & doc conventions

### 4.1 ADR naming and format

- Location: `docs/adr/`. Scheme: `NNNN-kebab-slug.md`, zero-padded 4 digits,
  currently 0001–0103 with **intentional number reuse for batch streams** (e.g.
  three `0103-*`: `pi-gis-runtime-v3`, `cartographic-design-system-v4`,
  `data-artifact-workspace-foundation-v3`; also duplicated 0088, 0094, 0096,
  0099, 0101, and two 0077s). A new quality-platform ADR can therefore take the
  next free number **or** join the current batch number with a distinct slug.
- Format varies by age; current dominant format (see `docs/adr/0103-pi-gis-runtime-v3.md:1-5`,
  `0046:1-5`): `# NNNN. Title` → `**Date:** YYYY-MM-DD` → `**Status:** Accepted`
  (older ones also carry `**Branch:**`) → `## Context` → `## Decisions` (numbered,
  with tables) → `## Migration` / `## Rejected Alternatives` where applicable.
  Some later ADRs (e.g. `0063`, `0065`) compress to title + Context/Decision prose
  — short decision records are acceptable.
- Tone convention: decisions record *what is frozen and why*, frequently with
  explicit anti-goal ("no unified cartographic style module", "keep X as Y") and
  incident references (#564, #671, #700 style issue numbers).

Three representative ADRs to imitate:

1. **ADR-0046 — Performance Regression Harness** (`docs/adr/0046-performance-regression-harness.md`):
   Context cites the goal verbatim; Decisions include a workload/baseline table
   and the three-level gate formula. Model for any gate-defining ADR.
2. **ADR-0063 — Production fail-closed gate is CartographicQuality** (`docs/adr/0063-production-gate-is-cartographic-quality.md`):
   one-page decision record: problem, decision, what stays out of scope. Model
   for a scope-narrowing quality-policy ADR.
3. **ADR-0103 — Pi GIS Runtime V3** (`docs/adr/0103-pi-gis-runtime-v3.md`):
   full format with numbered decisions mapping 1:1 to code artifacts
   (`app/tools/descriptor.py` fields, descriptor coverage gate at `:51`). Model
   for a contract-surface ADR; this is also the ADR the descriptor coverage gate
   (G6) belongs to.

### 4.2 Subsystem architecture docs

- Top-level subsystem docs: `docs/gis-harness.md` (layer responsibilities table +
  pipeline diagram), `docs/cartographic-closed-loop.md` (L0–L4 evidence ladder),
  `docs/architecture.md`, `docs/data-v3/` (data plane), `docs/workflows/`
  (workflow subsystem: `architecture.md`, `recipe-dsl.md`, `authoring-guide.md`,
  `completion-contract.md`, `conformance-corpus.md`, `fallback-semantics.md`),
  `docs/science/` (CONTRACT_BACKBONE.md, FOUNDATION_V3.md, architecture.md),
  `docs/inspection-standard.md` (versioned living ops doc: `版本 v0.1.3 · 状态:
  活文档` header at `:3`).
- Dev-stream working docs: `docs/dev/<stream>/{audit,plan,decisions,patterns,progress}.md`
  (see `docs/dev/spatial-algorithm-v3/`) — read-only audit first, then phased plan
  ("每阶段独立 commit"), decision log, progress log. A quality-platform workstream
  should follow this five-file layout.
- Catalog doc format: generated header ("自动生成 / 由 registry 生成，请勿手工编辑",
  truth pointer, regen command), stats line, per-domain sections, bounded bullets;
  bilingual (zh-primary) prose with code identifiers in backticks.
- Authoring-guide conventions: `docs/workflows/authoring-guide.md:5-14` opens with
  "只读 registry，不复制" (read registries, never copy facts) and enumerates the
  frozen vocabularies with counts — docs teach consumers to reference, not duplicate.

## 6. Certification precedents

Nothing is named "certification" as an artifact, but four certification-*shaped*
mechanisms exist — these are the precedents to generalize:

1. **Scientific status = evidence-grade certification.**
   `AlgorithmDescriptor.scientific_status` (`algorithm_registry.py:135,450-461`)
   is a declared certification level enforced mechanically: `PRODUCTION` requires
   native runtime + parameter contract + method references + conformance tests;
   `VALIDATED` requires conformance tests; `DEPRECATED` requires a declared
   fallback. `conformance_tests` holds ≤8 pytest node ids whose file existence is
   validated (`:151-158`) — i.e., a descriptor already points at its own
   certifying tests, and the repo checks they exist. `CONTRACT_BACKBONE.md`
   §2 documents the table and the "never claim PRODUCTION without…" rule.
2. **Uncertainty declarations.** `app/lib/gis/uncertainty.py:1-16` defines a
   closed `UNCERTAINTY_TYPE_VOCABULARY` (7 types: scalar/field/raster
   uncertainty, statistical significance, sensitivity envelope, validation
   metrics, Monte Carlo summary); descriptors declare `uncertainty_outputs` and
   "declared ⇒ must actually be emitted by the implementation" (validate()
   enforced; `CONTRACT_BACKBONE.md` §4). Bounded blocks, full surfaces via refs.
3. **Scale/latency declarations.** `BackendVariant.min_features/max_features`
   scale windows (`algorithm_registry.py:70-88`) consumed by the pure-function
   `backend_selection.select_backend()` (`app/lib/gis/backend_selection.py:83-153`,
   "声明序优先", holes → first unbounded variant); decision written into evidence
   diagnostics; decision contract pinned by
   `tests/benchmarks/test_backend_scale_decisions.py` (typed
   `ResourceScaleMismatch` rejection, "no fragile wall-clock" methodology). Tool
   side: `scale_class` / `latency_class` / `memory_class` descriptor fields
   (`registry.py:450`, ADR-0103 decision 1) — currently gated only by the broken G6.
4. **"Certify" semantics in the runtime evidence ladder.** `docs/cartographic-closed-loop.md:13-19`
   defines L1–L4 (tool validity → map-state → structural → cartographic quality);
   a strict freshness/ownership rule recurs across the code: *"a stale/foreign
   observation cannot certify the mutation"* —
   `app/lib/harness/pi_agent_harness.py:68,119,987,1267`,
   `app/services/mapspec/lifecycle_engine.py:73` (strictly newer sequence
   required), `app/lib/cartography/semantic_checks.py:643,1820`. ADR-0065 adds
   the promotion precedent: runtime probes are hard gate assertions (not scored
   dimensions) with a two-phase promotion rule (nightly → PR-blocking requires
   consecutive greens + time bound) — the exact pattern a new certification gate
   should reuse for promotion policy.

Also relevant: fallback declarations are mandatory and graded
(`fallback_semantics`: equivalent/approximation/proxy/degraded/not_allowed,
`algorithm_registry.py:33-35`), i.e. *degradation certification* already exists
in vocabulary form.

## 7. Known limitations & migration-note conventions

### 8.2 How generation hooks into registry introspection

1. Generator imports the three registries via the existing singleton getters
   (`get_capability_registry()`, `get_algorithm_registry()`,
   `get_parameter_contract_registry()`) and builds a ToolRegistry the way tests
   do (`init_tools(r)` — see `test_tool_meta_contract.py:24-29`) so the manifest
   reflects the live registration surface, then calls
   `compile_quality_manifest()`.
2. Iteration must be sorted (ids; algorithms by `(priority, id)` within
   capability — same order as `gen_science_catalog.py:77-87`) and all text bounded
   (160-char caps, list caps) to keep byte-determinism.
3. Per-entity quality record = descriptor declarations **+ verification links**:
   `conformance_tests` node ids resolved against the file tree, oracle-domain
   coverage counted from `tests/science_oracles/data/*.json`, manifest issues
   folded in with severity. Anything unverifiable at generation time renders as
   `"unverified"` — the manifest must not fabricate evidence (mirror of
   ADR-0103's "capability provenance, never fabrication").
4. Thresholds/weights (what counts as certified) live **once**, in the quality
   package constants, and are *rendered into* the manifest header — CI contract
   tests pin workflow ↔ constants, exactly like `--cov-fail-under=75` is double-pinned.

### 8.3 Surfacing drift reports

- Primary surface: pytest failure messages that name the regen command (existing
  convention, e.g. `test_foundation_v2_infra.py:183-185`). Add a `--check` mode
  to `gen_quality_manifest.py` so CI/deploy can run it without pytest.
- Secondary surface: manifest carries `content_fingerprint`-style digests per
  section (pattern: `recipe_content_fingerprint` rendered into the workflow
  catalog, `gen_workflow_catalog.py:141`), so a stale manifest is diffable per
  entity, not just byte-wise.
- Runtime surface: fold manifest staleness into the existing
  `CompiledRuntimeManifest.is_stale_plan(fingerprint)` mechanism
  (`runtime_manifest.py:103`) if the quality manifest becomes startup-loaded —
  one staleness semantic, not two.

## 9. Key risks (second-source-of-truth pitfalls)

1. **Do not re-introspect registries with new code.** If the QualityManifest
   generator walks tools/algorithms with its own logic instead of reusing
   `runtime_manifest` projections, counts and capability mappings *will* diverge
   (the repo already fought this class of bug: #678 domain-vocabulary contract,
   #694 FrozenCatalog stub — the reason the contract tier exists, `ci-local.sh:48-51`).
2. **Do not let the manifest become an editable registry.** Generated files must
   keep the "请勿手工编辑" banner + drift test; the moment someone "fixes" the
   manifest by hand, it is a second truth. Conversely, thresholds must NOT live
   in the generated artifact (artifact = projection; thresholds = code constants
   rendered for display only) — otherwise editing the manifest changes gate behavior.
3. **Do not duplicate the CI ratchet.** Any quality threshold added to
   `production.yml` must be mirrored by a contract test in the same PR
   (`test_ci_perf_coverage_contract.py:196` states the rule verbatim: "Do not
   raise this number independently of the workflow"). A QualityManifest that
   *also* hardcodes thresholds creates a third copy — render, don't define.
4. **G6 is broken in this snapshot** (`test_descriptor_coverage_gate.py:9`
   imports a missing `scripts/check_tool_descriptor_coverage.py`; ADR-0103:51
   documents it as existing). Either the snapshot predates/postdates the script
   or it was lost — the quality platform's first concrete deliverable should be
   restoring it *on top of* the manifest compiler, not alongside it, or the
   platform ships with a red baseline and no one will trust its gates.
5. **Certification vocabulary sprawl.** `side_effect`, `scientific_status`,
   `fallback_semantics`, `crs_class`, `uncertainty_outputs`, `security_tier` are
   six already-closed vocabularies owned by different modules. A certification
   layer must *map* these, never define parallel enums; new vocabulary requires
   the "report it, don't edit the central file" protocol
   (`CONTRACT_BACKBONE.md` §2/§8).
6. **Byte-determinism hazards**: dict iteration order, unbounded prose fields,
   float formatting (see `r9()` in `gen_science_oracles.py:78`) and timezone-dependent
   timestamps are the four ways a generator breaks byte-diff gating. No timestamps
   in generated output (existing generated docs contain none).
7. **Promotion discipline**: new gates should follow ADR-0065's two-phase rule
   (nightly-first, PR-blocking only after consecutive greens) — making an
   unstable quality gate PR-blocking immediately would repeat the failure mode
   the runtime-validator lane was built to avoid (`production.yml:493-497`).
