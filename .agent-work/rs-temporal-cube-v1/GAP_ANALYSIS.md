## Genuinely missing — BUILD

1. **Agent-facing TemporalRasterCube *descriptor* (refs-only)**. The in-memory `TemporalCube` (numpy) and the storage-level RS labeled cube exist, but there is **no descriptor contract** that names assets/times/bands/polarization/grid/crs/quality/cloud/shadow/nodata/source_version *as refs* for LLM/planner consumption (the D1 analog for cubes). `rs_cube.py` deliberately refuses to do source resolution itself (delegates to `cube_service`), and `science_temporal_tools` warns "完整特征面走 artifact/ref 通道" but no descriptor type exists. → build `TemporalRasterCubeDescriptor` (pydantic, additive-style like `contracts.py` D1).
2. **Optical/SAR acquisition alignment engine**. `rs_cube` requires *pre-aligned* grids and typed-refuses misalignment ("对齐是上游职责"); `acquisition_comparability`/`stack_comparability_warnings` check SAR meta comparability, but **no component pairs optical and SAR acquisitions across time windows / grids / CRS and produces an alignment plan or typed misalignment report**. This is the biggest true gap.
3. **Typed gap semantics**. Gaps today are: count strings in `cube.disclosures`, `gap_lengths()` ints, and two typed rejections (misaligned grid, partial time axis). No **typed gap taxonomy** (e.g. `missing_acquisition` vs `cloud` vs `shadow` vs `nodata` vs `layover` vs `unregistered`) with per-pixel/per-slice provenance and ratio disclosure. `RS_ROLES` has cloud_mask/quality_mask roles but no unified typed gap mask.
4. **Pluggable preprocessing plan for RS cubes**. `modelops/preprocess.PreprocessPlan` is model-window oriented (chips/normalization). Nothing composes sar_filter → sar_calibration → cloud_qc → gap policy as a declared, replayable **plan** over a cube (and #1335/#1336-adjacent modelops churn argues for a new module, not extending modelops).
5. **SAR VV/VH × NDVI/EVI joint feature stack**. `vh_ratio` produces a VH ratio surface; `compute_spectral_index` produces NDVI/EVI; **no cross-modality joint stacking/fusion builder** (per-pixel feature matrix with provenance + per-feature validity). Feature-level / late evidence fusion recipes: none (`evidence.py` is quality-evidence only).
6. **Polygon/patch sample attachment with geographic split**. `spatial_sampling` makes points; `cv.spatial_block_folds` folds point coordinates; `modelops.evaluation.spatial_blocked_split` is pixel-grid based. **No attach-polygons→cube-features→spatial-block-split pipeline that yields train/val sample tables (refs, not payloads) with leakage disclosure.**
7. **Consolidated disclosure block**. Pieces exist (layover_shadow_mask, cloud_qc, slice_spacing_report, calibration_evidence_facts, QualitySignals) but no single **coverage/quality disclosure record** aggregating gap ratio, cloud/shadow %, layover/shadow %, registration residuals, source versions — the "honest coverage card" the runtime should attach to products/evidence.
8. **Yearly/seasonal temporal feature orchestration at cube level**. Climatology (`TemporalCube.climatology`) + phenology + percentiles exist per-module; no *yearly/seasonal composite → features (median/percentile/amplitude/slope/changepoint/phenology-proxy)* orchestrator that runs over a descriptor + emits refs. Keep as orchestration + thin new math only where missing (e.g. per-water-year grouping, seasonal percentile composites).
9. **Temporal raster MapProduct recipe**. `recipe_packs/temporal.py` covers *vector* station profiles; no raster temporal-cube product recipe (map + chart refs + table refs + disclosure). MapProductVersion plumbing already supports it (`compute_plan`, `artifact_ids`, chart/table artifact types).
