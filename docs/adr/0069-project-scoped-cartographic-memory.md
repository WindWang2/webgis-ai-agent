# 制图记忆是项目域的，且不可跨越 fail-closed 边界

Date: 2026-08-23

## Status

Accepted

## Context

制图智能体此前的所有制图判断都是 session 级失忆的：verdict、样式修正、分类断点都随 session 消散。同一项目连续出图时每张图从默认值重新猜，违背制图学最基本的系列图规范（同一项目多张图的分类方案应当可比）。

`specs/cartographic-quality-rules-and-memory-spec.md` 的 Phase 2 引入项目级制图事实账本（`carto_project_facts`）。引入持久记忆意味着**评审证据第一次跨越了 session 边界**，这带来三个必须一次性钉死的语义问题，否则后续实现会逐步侵蚀既有的 fail-closed 纪律：

1. 记忆的作用域边界在哪（能否跨项目/跨租户复用"手艺"）；
2. 记忆是否可以**代替**证据（用"上次验证过"跳过本次评审）；
3. 记忆与新证据冲突时谁赢。

第 2 点尤其危险：记忆的天然诱惑就是"缓存结论"，而 ADR-0060/#644 建立的规则是 missing evidence 恒为 `not_evaluated`/0.0，绝不放行也绝不满分。若记忆能充当证据，整条阶梯的诚实性一次失守。

## Decision

1. **记忆严格是 project 域**：账本按 `project_id` 分区，查询恒带 project 谓词。禁止跨项目"全局制图手艺库"——那会把一个租户的数据画像/偏好泄漏给另一个租户（多租户隔离纪律高于复用便利）。无 project 上下文的会话零行为变化、零额外查询。

2. **记忆是先验，不是证据**：注入的事实只影响**下一次作图的起点**（默认色带、共享分类方案、偏好），永不参与 verdict 计算，永不使某条规则跳过评审。每一张新图仍然要自己产出确定性证据才能过 gate。账本里的 `validity_tier` 是"当时那次评审的结论"的历史标签，不是本次的通行证。

3. **冲突显式化，绝不静默覆盖**：新 turn 产出的分类断点与账本中 `shared_classification` 的指纹不一致时，事实转 `conflicted` 并在证据中记录分歧，由用户/下一轮修复裁决。共享方案只允许**显式升级**（新方案自身评审通过）。`conflicted`/`stale` 的事实一律不注入——注入一个自己都不确定的先验比不注入更坏。

4. **记忆有界且可整体关闭**：每项目条数上限（默认 200，按 `last_verified_at` LRU 淘汰），注入块字符预算与 `[CARTOGRAPHY_VERDICT]` 同量级。账本不可用/注入失败时降级为"无记忆"，与 Phase 1 之前的行为完全一致——记忆是增值上下文，永不阻断对话。

## Consequences

- 账本写入点只在**评审结论已经产生之后**（gate 通过、用户修正、recipe 完成），因此记忆永远滞后于证据一个身位，不可能被用来短路评审。
- 若未来要做"跨项目制图偏好"（如用户级口味），那是一个需要显式租户隔离设计 + 本 ADR 修订的功能，不是可以顺手扩大的查询范围。
- 若未来希望用记忆加速评审（跳过已验证图层的规则），必须修订本 ADR 的第 2 点；在此之前"记忆命中"只允许改变作图起点，不允许改变判定。
- `conflicted` 状态会积累，需要 UI/裁决入口（spec 开放问题 2）；在入口就绪前，冲突事实只是"不注入 + 可审计"，不会自动清理。
