# Independent final review: core repairs and backend failures

This ledger records the four findings assigned after the independent working-tree review, plus the exact backend failure group assigned to core. It supplements the original 152-issue closure audit; it does not relabel empty issue descriptions or claim that the entire backend gate is green.

## Independent review findings

| Finding | Disposition | Implementation and authority boundary | Meaningful regression |
| --- | --- | --- | --- |
| HTTP replay reauthorizes only the user, bypassing changed session/resource authority | fixed | `app/core/idempotency_identity.py` permits replay only for the three JSON session endpoints whose entire resource policy is `require_owned_session` (canvas actions, cartographic observation, clarification answers). It validates the live user **and** the current Conversation owner/capability even when both Bearer and X-Session-Token are supplied. Unknown resource policies execute the real route without reading or writing the cache. `app/core/idempotency.py` excludes owner-token rotation before any cache access; credential issuance can never replay a cached new token. | `tests/unit/test_review_final_idempotency_authority.py`: real SQLite users/conversations, signed Bearer, real HTTP dependencies and rotation endpoint; old anonymous token plus valid Bearer is rejected after rotation, changed authenticated owner cannot replay, rotation writes no idem records, unproven project policy executes again. Existing live role/revocation test now uses a real owned session. |
| Required server-owned session_id is hidden from schemas but validated before injection | fixed | `app/tools/registry.py` overwrites `session_id` from the trusted dispatch argument **before normalization and validation**, only for models that declare that field. The later function-signature injection remains. None cannot fall back to a caller-supplied victim session; a required string fails validation without a trusted session. | `tests/unit/test_review_final_dispatch_authority.py`: real composition tool registration and real dispatch; hidden required field succeeds with trusted context, forged argument is replaced, absent context cannot invoke the ownership guard. |
| Control refs bypass data capacity, leaving plan-id/ref:plan history unbounded | fixed | New `app/services/session_control_budget.py` gives all control refs a separate 64-ref / 50 MiB UTF-8 serialized payload budget. Memory insertion/overwrite preflight and eviction occur under its store lock; Redis watches control payloads, order and aliases and commits retention plus the incoming write in the same transaction. Current aliases, their control-ref dependency closure, latest checkpoint, and active unaliased legacy plans are protected. Old retired/unaliased history is evicted; if protected live state cannot fit, the incoming write is rejected before mutation. Both insert and overwrite use actual encoded bytes. Alias/revision/digest/descriptor/cache cleanup accompanies eviction. Existing session-plan archive retention remains. | `tests/unit/test_review_final_control_and_settle.py`: both backends at data capacity one; repeated plan-id history stays bounded while user data, current envelope, referenced older checkpoint and latest checkpoint survive; failed oversize overwrite leaves old payload/alias intact; UTF-8 byte enforcement; active plans are never evicted to admit new history. |
| Durable settle token strands interrupted turns as duplicate/running forever | fixed | `harness_kernel/settle_claim.py` distinguishes in-progress ownership, completed ownership and an expired claim. The lease is 90 seconds; coordinator effect execution is bounded to 60 seconds. Expired claims receive a fresh random token via the shared session-plan CAS. `runtime.end_turn` checks the token before terminalization; completion marking also requires the current token and a terminal turn. Cancellation/timeout/unexpected interruption cancels effects and runs bounded shielded interrupted terminalization. Failed authority writes never populate the process receipt cache. `PlanTurnRecord.settle_finished_at` is additive envelope metadata, not a database migration. | Same control/settle regression file: Memory and Redis cancellation leaves terminal interrupted state; receipt-cache loss cannot strand the turn; a fresh Redis-backed runtime reacquires expired ownership; old token cannot end or complete the new claim; live claims return in_progress, completed turns return duplicate. Existing concurrent-claim regression now distinguishes in-progress from completion. |

Settlement takeover occurs on a subsequent settlement attempt after lease expiry. Projection effects are idempotent/retryable domain operations; this is not an exactly-once guarantee for arbitrary external side effects. If durable storage cannot persist cancellation cleanup, the retained token expires rather than permanently blocking recovery.

## Exact backend failure group

| File/group | Disposition | Cause and repair |
| --- | --- | --- |
| `tests/integration/test_cross_tenant_isolation.py` | fixture corrected | Both existing seeded users and their resources already lived in a temporary SQLite database, but optional live identity lookup still used the application database. Bind both live-auth session seams to the same temporary database and reset the live-user cache. Positive owner reads and negative cross-tenant checks now exercise actual persisted users; no authorization dependency was bypassed. |
| `tests/integration/test_cross_tenant_matrix.py` | fixture corrected | The same separate live-auth database mismatch caused 401 before the resource ACL. Its synchronous and asynchronous stores and live authentication now share the isolated database. Cross-organization read/write rejection remains asserted. |
| `tests/integration/test_quality_v3_trace.py` | obsolete expectations corrected | All-f trace IDs are nonzero and valid; unknown trace flag bits do not invalidate inbound trace context. They are now explicit positive cases. The parser's old comment was corrected; parsing behavior was preserved. Basis: [W3C trace-id](https://www.w3.org/TR/trace-context/#trace-id), [W3C other flags](https://www.w3.org/TR/trace-context/#other-flags). Version ff and all-zero IDs remain invalid. |
| `tests/unit/test_plan_orchestrator.py` | fixture corrected | `plan_store.peek()` returns a defensive copy. The simulated failed step must be placed in the orchestrator's actual in-flight canonical plan before flush. The test still verifies persisted partial completion and restart continuity. |
| `tests/test_chat_engine_planning.py` | real deadlock fixed; fixture corrected | `PlanStore.save/supersede/clear` acquired the same non-reentrant session lock already held by a legacy chat turn, so tick flush timed out and never persisted progress. All three canonical plan writers now use the same independent `plan-store:{session}` distributed key, retaining fail-closed locking and payload revision CAS. A regression saves inside an actual parent session lock with a bounded deadline. The old-goal history test also explicitly flushes its synchronous setup before expecting durable history. |
| `tests/integration/spatial_events/test_api.py` | real webhook bug fixed; fixture corrected | The verified-HMAC route omitted the now-required `trusted=True` constructor marker, rejecting valid deliveries. The marker is passed only after org-secret selection and HMAC verification; invalid signature and unconfigured org remain denied. The portfolio binding case now seeds a real live user/org/project and uses its isolated DB for the project authorization seam instead of requesting a nonexistent project. |
| `tests/integration/spatial_events/test_failures.py` | real window bug fixed; fixture corrected | Out-of-order arrival discarded already observed newer timestamps and could never fill the intended event-time window. `spatial_events/watch.py` uses a monotonic watermark derived solely from observed times, retains only observed events within the bounded window, and never regresses the window on late delivery. The mission lease conflict fixture now binds its mission and event to the same session, preserving the tightened mission candidate scope and the actual lease-conflict/retry assertions. |
| `tests/test_zero_review_authz.py` | obsolete expectation corrected | Missing conversations are deliberately rejected before materializing refs. The missing-session case now requires 404, alongside foreign-owner, legacy anonymous and wrong-capability denial. |
| `tests/unit/test_production_secret_entropy.py` | fixture isolated | Strong-secret production tests explicitly disable public registration and runtime skill upload. They test secret entropy without inheriting a test-suite/developer registration setting that production correctly refuses. The production startup guards were preserved. |
| `tests/unit/test_turn_settlement_seam.py` | coordinator seam fixture updated | The explicit mock now provides a typed claim token and completion result and accepts the runtime's token parameter. Actual persistent ownership/recovery is covered by the independent Memory/Redis tests above. |
