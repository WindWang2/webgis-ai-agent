Independent extra finding (reported to core, beyond the original add/mark_deleted row): `compact()` index-first replacement followed by metadata failure is NOT a full transaction. Minimal real-FAISS repro: add vectors for deleted/B/C, soft-delete the first, fail `_atomic_write_json` during compaction, create fresh store, query exact C vector: returns B with score 1.0 after recovery truncates old metadata. Stale row-position recovery cannot reconstruct a reordered compacted index. Core explicitly delegated this extra defect; **fixed and verified** in `rag/pair_transaction.py` plus store integration. Before compaction replaces either file, immutable backups of the preceding pair and a fsynced pending marker are established under the store sidecar lock. Both writes must finish before removing/fsyncing the marker commits the pair. Write errors restore the old pair; process death leaves the marker so the next warm or cold reader rolls back before opening either file. Rollback retains immutable backups until completion, making interrupted rollback replayable. Damaged/missing recovery evidence fails closed. Search holds the same lock across index and metadata use so it cannot observe an in-progress pair. Compaction also deep-copies cached metadata. Existing add/mark/delete ownership semantics remain unchanged. All five touched source files pass targeted mypy (`/tmp/data-s99-mypy109.log`); numeric HTTP deadlines now use the typed `aiohttp.ClientTimeout` equivalent and the corresponding timeout test checks the actual total deadline.

Additional real-FAISS regressions cover metadata failure after index reordering, retained cached rows, successful retry; a fresh Python subprocess exits via `os._exit(71)` precisely between file replacements and warm/fresh readers recover correct B/C identity; missing backup denies both search and metadata access; a paused writer blocks a competing reader until the new pair is committed. Interrupted rollback with the first file already restored is retried using both retained backups; failed compaction to an empty index restores the original index file and metadata byte-for-byte. No failed compacted pair is described as repairable merely by matching row counts.
