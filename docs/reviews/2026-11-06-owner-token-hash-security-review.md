# Anonymous owner credential hash-chain peer review — 2026-11-06

Independent, scoped source and behavior review of #1860 S1-055. Production sources were read only; the implementing core agent owns the corrections below. This is not a claim of a complete infrastructure or penetration audit.

| Chain / finding | Disposition | Evidence |
| --- | --- | --- |
| Conversation and AnalysisTask persistence | verified | Both columns use OwnerTokenColumn. SQL bind hashes a plain presented token, while ORM-loaded values retain OwnerTokenDigest. A raw SQL read exposes only SHA-256. A database equality query hashes transport values, so replaying the plain stored digest does not match. |
| Standard HTTP/history/WebSocket ownership | verified in inspected paths | owner_token_matches rejects a typed presented verifier and hashes a plain presented token against the typed expected verifier. History authorization and collaboration handshake/watchdog pass the ORM value without converting it to a plain string. lookup_session_owner_token preserves the type. |
| Initial issuance and internal history | verified in inspected paths | get_or_create_conversation_with_created carries the generating request's raw value via _issued_owner_token. Existing requests receive no token from _pi_stream_capability; load_context returns only the newly issued value or its caller's presented value, never the stored verifier. A concurrent insert loser is marked existing. |
| Signed terrain and session-data proof | verified in inspected paths | A ref/session-bound exp/sig is verified before the route forwards its ORM-loaded typed verifier internally. Ordinary header/query/JSON strings are hashed again by the session-data guard; a transported database digest fails. The typed proof is not placed in the generated terrain URL. |
| Migration / rollback | verified | Migration 0102 reflects plain SQL columns, processes at most 500 ordered rows at a time for both string and integer primary keys, and hashes once. Downgrade revokes anonymous credentials by clearing verifiers rather than treating their hashes as raw tokens. Documentation explicitly requires migration before new traffic. |
| Target resolver directly compares the stored digest | **fixed by core, independently verified** | The original direct hmac.compare_digest accepted a plain database digest and refused the raw token. The fallback now calls owner_token_matches; the permanent behavior regression proves raw success and digest refusal before any ref-store access. |
| Concurrent anonymous token rotation splits DB/cache truth | **fixed by core, independently verified** | The original A mirror → B mirror → B commit → A commit schedule produced mismatched verifiers. The new owner_token_rotation helper ends the dependency's old snapshot, takes the shared authoritative session lock, SELECTs FOR UPDATE with populate_existing and revalidates the presented credential. Two old-token requests now produce one success and one 404 with consistent DB/cache truth. On failure, rollback precedes a fresh database verifier lookup; a lost lease does not publish compensation. |
