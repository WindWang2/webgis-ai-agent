# 子代理派工协议（#700 流程硬化）

夜班（#676–#694 清扫，2026-08-20/21）实证记录：单夜 17 次子代理空返回
（"Model returned no text"，provider 侧故障，与任务大小无关），同期维护者
直接实现 6 张票零失败。本协议把当晚的隐性做法固化为显式规则。

## 何时派子代理

- 任务可并行（与在途工作**模块零交集**——先 grep 双方要动的文件清单）。
- 工单自足：票面证据 + 已定设计方向（"不要重开"清单）+ 流程硬规矩 +
  报告格式，一次写全。子代理没有会话上下文。
- 反例：需要跨票上下文的判断（如"这个文件属于在途 #690 的边界"）——
  写进工单，否则子代理会越界。

## 死亡协议（空返回 / 无输出终止）

1. **查残留**：`git -C <worktree> status --short` + `git log --oneline -2` +
   `git diff --stat`。三种情况：
   - 零残留 → 原工单重派（附"此前无输出终止零残留，从零开始"）；
   - 有未提交半成品 → **读 diff 评估成色**：符合工单设计就续完（补测试 +
     验收），跑偏就丢弃重做（#684 案例：半成品设计正确，续完省一半工）；
   - 有已提交的完整工作 → 当作交付走验收链。
2. **两振切人工**：同一票第二次死亡（或首次死亡且残留不可用）→ 维护者
   直接实现。夜班数据：直接实现 6 张零失败，且评审一次过的比例更高。
3. provider 级故障（连续秒失败，如 "Model provider is not configured"）
   → 停止派工，全部转人工直到恢复。

## 工单必备要素（缺一会被打回重来）

- 行号以当前代码为准的免责声明 + "以当前代码为准"
- 已定设计方向（"不要重开"清单）——防止子代理重新设计已决事项
- flip-red 纪律 + **先 commit 再 flip-red**（#687 教训）+
  "commit message 不写 Fixes/Closes"（关票由维护者带验收评论手动做）
- 门禁要求：`--fast` 必须；动 registry/catalog/engine/dispatch 面 →
  **全量后端 lane**（根目录契约测试盲区，见 #678/#694 两次事故）

## 验收链（维护者侧，不可委托）

flip-red 亲手复证（用 `scripts/flip-red`）→ 仓级门禁 → 两轴评审
（`/code-review`）→ 硬发现全修 → 合并推送 → 关票附验收对照与已知取舍 →
盯 CI。
