# PLAN — GOAL-20261126-02 任务驱动数据覆盖与供给

## 里程碑

- M0（当前）：B 节核对 + 基线勘察 + R0 基线验证 → 证据矩阵
- M1：WP1 任务数据需求合同（TaskDataRequirement 投影、角色绑定、可追溯）
- M2：WP2 空间-时间覆盖矩阵（声明/相交/可核验/完备性分层 + CRS/跨日期线）
- M3：WP3 受预算多候选供给计划（组合 ADS/fabric，幂等、partial、替代）
- M4：WP4 Agent+UI 工作台（有界工具面 + 数据卡，双入口）
- M5：WP5 真旅程基准（≥4 场景 + 性能/科学 oracle）
- M6：WP6 独立 review（R1/R2）+ 修复 + PR

## 每 WP 循环（D 节纪律）

复核现状 → 失败用例/独立 oracle → 最小实现 → 真实接线 → 正/负/并发验证 →
review → fix → regression → commit → ledger 更新

## 完成判定（终止条件）

1. ≥4 场景从自然语言 → 角色绑定 → 现有分析/制图工具真实调用（fixture 模拟外部服务时显式标注）
2. 覆盖/缺口、来源/许可/时间/版本/科学适用性/成本说明可信有界
3. 已批准计划经现有生产数据面生成合格 ref；部分失败/取消/过期诚实分流
4. 独立 reviewer 确认无本线 P0/P1
5. PR 已提交（或真实阻塞已记录）

## 风险与对策

- ADS 真实形态未知（等勘察 B 报告）→ WP3 严格组合不复制
- 前端接线成本高 → WP4 优先现有数据工作台组件最小扩展
- 命名冲突 → task_data_supply 需 grep 去重（勘察 A）
