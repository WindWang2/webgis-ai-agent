## 1. Project / tenant model

**Entities (`app/models/project.py`)** — one DB, ten tables in this file: `projects` (:16), `project_datasets` (:44), `workflows` (:84), `workflow_revisions` (:129), `workflow_runs` (:152), `workflow_resume_anchors` (:216), `artifacts` (:231), `artifact_lineages` (:277), `artifact_revisions` (:332), `carto_project_facts` (:402), `map_products` (:462).

- **Project identity**: `id = f"proj_{uuid4().hex[:16]}"`, columns `org_id`, `owner_id`, `status`, `metadata_json` (`app/services/project_service.py:97-108`).
- **Tenancy gate**: `_caller_may_access_project(project, user_id, org_id)` (`project_service.py:23-63`) — owned rows: owner or same-org only; ownerless rows: different-org denied, no-org-claim (incl. anonymous) allowed. This is *the* isolation point every project-scoped read goes through (`get_project_with_auth` :115-129).
- **Datasets**: `ProjectDataset.id = "ds_<16hex>"`; attach computes deterministic `version_fingerprint = compute_dataset_fingerprint(source_type, source_ref, crs, schema_profile)` (INV-FP1/2/3) (`project_service.py:368-390`). Detach is a soft tombstone (`detached_at`, INV-DEL1) (`project_service.py:479-485`). Quality status closed vocab: unchecked/valid/warning/repairable/blocked (`project_service.py:447-457`).
- **Workflows**: `wf_<16hex>`, immutable `WorkflowRevision` (`wfrev_<16hex>`) with `graph_fingerprint`; revision publish is idempotent (same fingerprint reuses revision; `revision_no = max+1` with unique index + IntegrityError retry) (`project_service.py:563-653`). Runs: `WorkflowRun` rows scoped `project_id` (`project_service.py:743-759`).
- **Existing project read-model precedent**: `get_project_context_summary` / `get_project_fingerprint` (`project_service.py:131-290`) read only scalar aggregates (counts + max-modified) into frozen dataclasses `ProjectFingerprint` / `ProjectContextSummary` (`app/services/project_context_types.py:29-99`); `ProjectContextSummary.render()` emits the byte-stable `<active_project_workspace>` block (:83-99). A process LRU (`app/services/chat/project_context_cache.py`) keyed by `ProjectFingerprint.cache_key()` is invalidated on every mutation via `_invalidate_project_context_cache` (`project_service.py:66-83`, called at :353, :394, :484, :587, :712). **This fingerprint-on-read + invalidate-on-write pattern is the exact staleness template to reuse.**

## 2. gis_memory (ADR-0183/0190) — the memory store we must NOT re-implement

Package `app/services/gis_memory/` (contract/store/retrieval/projection/proactive_retriever/associative_index/memory_consolidator/harvest/queries/policy/sanitizer/pending/eval all exist; no other files).

- **Data model**: single table `gis_spatial_memories` (migration 0080) via `GISSpatialMemory` (`app/models/spatial_memory.py:45-111`): `org_id` NOT NULL indexed (:52), `scope ∈ session|project|user` + `scope_id`, 10-kind closed vocab (`contract.py:18-40`), `status ∈ active|superseded|invalidated` (:47-49), `invalidation_rule ∈ ttl|dataset_version|manual|scope_gone` (:51-60), `supersedes_id` chain, `fingerprint` (sha256 of kind+subject+semantic value, `contract.py:167-184`), partial unique index on active key (`spatial_memory.py:104-111`).
- **Write gate**: `MemoryWriteRequest.validate()` requires `org_id` (fail-closed tenancy, `contract.py:213-215`), evidence source must be in the per-kind allow-matrix (`contract.py:84-98`), value budget `VALUE_CHAR_BUDGET = 2048`, `REFS_MAX = 8` (:128-131). `store.record_memory` = sanitize → policy → supersede-chain/budget (`store.py:96-249`) with SAVEPOINT race handling (:225-247). Preference kind routes to ADR-0069 `carto_project_facts` (single preference truth) (`store.py:252-283`). Row budgets: session 80 / project 400 / user 200 (`store.py:48-53`).
- **Storage backend**: synchronous SQLAlchemy free functions; caller owns commit; production seams use `safe_record_memory` fail-safe wrapper (`store.py:1-13, 286-296`).
- **Retrieval** (`retrieval.py`): six mandatory filters (org/scope/active/not-expired/sensitive/version-compat) then scoring with readable reasons, deterministic order, top-k default 8 hard cap 16, `READ_CONFIDENCE_FLOOR = 0.5` (:31-176). Version-compat filter drops stale dataset memories when caller passes `dataset_versions` (:108-116).
- **What "projection.py" already does**: it is **not** a stored projection — it renders retrieved hits into the bounded `[GIS_MEMORY]` prompt block (`MEMORY_BLOCK_CHAR_BUDGET = 1100` chars, per-line `_xml_fence` escaping of untrusted strings, sensitive rows re-filtered, ellipsis-with-receipt when over budget, per-line fail-open) (`projection.py:32-33, 122-165`).
- **Proactive layer** (ADR-0190): `AssociativeIndex` — process-local per-org index with tokenized BM25-ish scoring, bbox-grid spatial candidates, half-life decay (`associative_index.py:143-487`); `ProactiveRetriever` resyncs from DB on staleness and only loads caller-named scope instances (`proactive_retriever.py:293-377`); `MemoryContextCard` (card_id/family/title/summary/resolved_place/bbox/score/reasons) + `awake()` produce bounded cards (`proactive_retriever.py:171-198, 406+`).
- **Harvest/pending**: turn-end harvest stamps org via `_gis_memory_org` in map_state and calls `invalidate_for_dataset` on version drift (`harvest.py`, `queries.py:18-19`); in-turn candidates buffer per-session ≤32, memory-only (`pending.py:14-32`).

## 5. Artifact registry / refs / revisions — staleness + big-payload mechanics

**Session-level (per-session, in session store):** `app/services/artifact_registry.py` — `ArtifactRecord` where **`artifact_id` IS the ref string** (`ref:geojson-…`) (:5-11, 86-117); lifecycle `valid → superseded → stale → expired` (:50-56); `ArtifactGraph` is a derived pure-function graph (consumers/producers/lineage/dependents/replacement_chain), never persisted (:9-11, 128-201); ledger persisted as session-store alias `artifacts`, bounded 128 records (:38-39, 204-260).

**Ref lifecycle — single invalidation authority:** `app/services/ref_lifecycle.py` — "invalidate ≠ delete"; `invalidate_ref_caches()` drops every process-local projection (spatial_index_cache, tile_lru_cache, ref_payload_cache) with explicit `RefInvalidationReason`, fires observer hooks via `register_ref_invalidation_hook` (:60-94, 101-169), schedules downstream staleness propagation on OVERWRITE/ROLLBACK via data_lifecycle `propagate_staleness` (:172-211), cross-process notification is best-effort (ADR-0101 D11).

**Ref payload = the big-payload ticket:** `ref:` ids are opaque 16-hex cursors into SessionStore; the LLM never sees payloads, the frontend fetches via `get_ref_data` (`CONTEXT.md` "ref_id (Cursor)"). `app/services/ref_payload_cache.py` caches *parsed* payloads per (session, ref) with 5s TTL + epoch guard against invalidate-during-build revival (:27-100).

**Durable project-level:** `project_artifact_promotion.py` materializes session refs → content-addressed BlobStore (sha256 key) + DB `artifacts` row with `content_fingerprint`, `storage_ref`, CRS/bbox/schema summary, producing capability/algorithm/tool triple; honest `ContentStatus` vocab incl. `session_expired`/`quota_exceeded` (:1-71). `artifact_revisions.py` = append-only revision ledger, **idempotent on `(artifact_id, content_sha256)`**, `revision_no` monotonic with unique-index race retry; DAO flush-only, caller commits (:56-134). `ArtifactLineage` edges are intra-project enforced (INV-LIN3), cycle-free (INV-LIN1/2), carry `source_dataset_id + source_dataset_fingerprint` (`lineage_service.py:35-140`, `app/models/project.py:275-320`). Disk GC: `artifact_lifecycle.py` purges exports/reports/uploads families (unrelated to logical staleness).

**Staleness semantics summary**: content identity = sha256 (revisions) / `content_fingerprint` (artifact row) / `version_fingerprint` (dataset attach); overwrite/rollback of a session ref propagates STALE downstream (ref_lifecycle :172-211); dataset version drift invalidates memory via `store.invalidate_for_dataset(org_id, dataset_key, version_token)` (`store.py:360-392`).
